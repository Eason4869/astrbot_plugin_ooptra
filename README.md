# Oopz 语音桥 · astrbot_plugin_ooptra

在 AstrBot 里管理 Oopz 语音房，共享所选群聊／私聊会话的人格和长期记忆。

当前版本：**2.0.0（dev 分支）**。本次未创建正式发布或标签。

> 此版本需配合 **[Ooptra 261019-dev 及以上版本](https://github.com/Eason4869/Ooptra/tree/dev)** 使用（对应预设正式版 **4.0.0**），人格与双向记忆依赖双方的 AstrBot 上下文协议 v1。请同时更新两个项目。

Ooptra 负责 Oopz 连接与音频对话；本插件负责会话映射、人格选择、记忆接入和 AstrBot 内的语音工作台。完整 UMO 保留平台实例名，避免不同机器人实例的同号群聊混淆。

## 功能

| 功能 | 在哪里使用 |
| --- | --- |
| 房间控制 | 工作台查看人数、麦克风／听音状态，一键进退房 |
| QQ 命令与 LLM 工具 | 查询语音、进退房、切换 Gemini Live／MiMo、控制自动串门 |
| 会话映射 | 一个域／频道可映射多个群聊和私聊，独立设置控制权限 |
| 内置人格 | 单选一个映射会话，跟随其人格或手选 AstrBot 内置人格覆盖 |
| 双向记忆 | 多选至多 8 个映射会话；查询全部所选会话，并写回全部所选会话 |
| 完整控制台 | 从 AstrBot 内打开部署中的 Ooptra 页面，配置模型、账号和更新备份 |

## 安装与连接

1. 按 [Ooptra 安装说明](https://github.com/Eason4869/Ooptra/tree/dev) 启动配套服务，完成账号登录与控制台密码设置。
2. 在 AstrBot 插件管理中安装本仓库的开发分支，或在插件目录执行：

   ```text
   git clone -b dev https://github.com/Eason4869/astrbot_plugin_ooptra.git
   ```

3. 安装插件依赖 `httpx`，重新加载插件。
4. 在插件配置填写 `api_base` 和 `api_token`，再打开插件工作台。

推荐 `api_base=http://127.0.0.1:3090`，`api_token` 填 Ooptra 控制台密码。AstrBot 与 Ooptra 分别在容器或不同机器时，填写 AstrBot 服务端能访问的 Ooptra 地址；浏览器自身的 `127.0.0.1` 不能代替部署地址。

使用当前带人格管理接口的 AstrBot。QQ 群、QQ 私聊与 Oopz 文字频道通过 `aiocqhttp` 会话目录选择；其他已启用平台可从最近识别会话选择或粘贴完整 UMO，实际记忆能力取决于所选记忆插件的支持与授权。接口缺失时会显示未就绪。

Oopz 文字桥接仍通过反向 WebSocket 单独连接 AstrBot；本插件不会替你创建该平台。

## 先映射会话，再选人格与记忆

在本插件工作台「会话对应」，或配套 Ooptra「语音台 → 会话对应」操作；两边共用同一份配置：

1. 选择 Oopz 域，以及“整个域”或“指定语音频道”。
2. 在「会话映射／控制入口」从 AstrBot 选择真实 QQ 群、私聊联系人或 Oopz 文字频道，也可粘贴完整 UMO，例如 `Bot:GroupMessage:12345678`、`Bot:FriendMessage:87654321`。Oopz 文字频道按名称选择，并校验对应 WS 实例身份。
3. 添加多个会话，可逐个关闭“允许控制”，保留它作为上下文来源。高级设置兼容一条映射包含多个域。
4. 切到「人格与记忆」：人格来源单选；记忆会话多选，最多 8 个，**查询与写回均覆盖所有选中会话**。人格覆盖留空时跟随所选会话，也可手选一个内置人格。
5. 选中私聊时，明确确认私聊上下文可用于公共语音房，且语音新记忆会写回这些私聊。
6. 保存规则。指定频道优先使用自己的规则，否则继承域默认；重新进房或刷新当前上下文生效。

也可以在当前会话发送管理员命令添加控制映射：

```text
/语音绑定 <域ID> [频道ID] [备注]
/语音映射
/进语音
/退语音
```

控制操作在多域映射中优先选 Ooptra 默认域，否则取第一个域。上下文则按实际进入的房间匹配独立来源规则。旧数字群号映射继续兼容；尚未保存独立来源时只兼容唯一绑定，多个匹配会提示选择来源。保存过来源规则后，即使删除全部规则，也不会自动改用其他控制会话。

## 开启人格与双向记忆

在工作台「人格与双向记忆」完成：

1. 开启同步。
2. 到「会话对应 → 人格与记忆」设置来源；「旧绑定默认人格」仅用于未单独设置来源的旧绑定。
3. 主记忆插件选择「自动识别」。安装多个受支持插件时，手选其中一个；选择「只同步人格」可关闭记忆接入。
4. 保存，重新进房；当前已在房时点击「刷新当前语音上下文」。刷新会重建模型会话。

语音房继承 AstrBot 人格后，Ooptra 原人格页会显示实际来源，并锁定本地人格编辑。停用同步并刷新当前上下文后恢复本地人格。

### 两个方向如何工作

- **会话 → 语音**：查询全部所选会话允许共享的记忆，合并结果并标明完整 UMO。
- **语音 → 会话**：向全部所选会话写回语音对话，逐目标保留回执；部分失败只补写失败目标。
- **明确要求记住**：调用记忆插件的写入接口，等待真实成功结果；普通对话的长期总结仍由记忆插件决定。

手选语音人格只改变语音扮演风格；每个记忆目标仍沿用各自会话的人格过滤。只有全部目标成功才可确认全部写入；普通对话“已采集”与长期记忆“已生成”分别反馈。不选记忆会话时仅同步人格。

### 支持的记忆插件

| 插件 | 方式与条件 |
| --- | --- |
| [Memory Companion](https://github.com/menglimi/astrbot_plugin_memory_companion) | 使用现有 Bridge 检索、语音时间线采集与明确写入；保留权限及采集控制 |
| [LivingMemory](https://github.com/lxfight-s-Astrbot-Plugins/astrbot_plugin_livingmemory) | 适配其群作用域、存储回执、历史限制、反思与长期记忆写入接口 |

检测的是已启用实例及实际接口；其他记忆插件需增加适配器，不会自动读写未知插件的数据库。Memory Companion 开启额外授权校验而尚未授权语音桥接时，不能绕过校验。第三方升级造成接口变化时，工作台会显示不兼容或失败状态。

### 成员身份

向真实 QQ 群写入时，若要关联 Oopz 发言者与 QQ 用户，可在 `context_identity_links` 显式配置：

```json
{"Oopz用户UID": "QQ号"}
```

未关联者保留 Oopz 来源身份；Oopz 文字会话不套用 QQ 号关联，私聊以选中的私聊会话归档并保留实际 Oopz 发言者元信息。不根据昵称猜测。成员独立会话请填写其实际完整 UMO；旧群号不能自动归并这类上下文。

## 常用命令

| 命令 | 用途 | 权限 |
| --- | --- | --- |
| `/语音状态` | 语音人数与成员状态 | 普通成员 |
| `/语音自检` | 配套服务连接检查 | 普通成员 |
| `/进语音 [频道]`、`/退语音` | 控制已绑定的语音房 | 受 `join_admin_only` 控制 |
| `/语音方案` | 查看当前后端 | 普通成员 |
| `/语音方案 gemini` 或 `mimo` | 切换语音后端 | 默认仅管理员 |
| `/语音串门 开` 或 `关` | 开关绑定域的自动串门 | AstrBot 管理员 |
| `/语音绑定`、`/语音解绑` | 管理群绑定 | AstrBot 管理员 |

查询、进退房和后端切换也可通过可选 LLM 工具调用。关闭 `enable_llm_tools` 后，工具返回禁用状态。一个 Ooptra 实例同一时间只有一个语音会话，后端、音量与进退房操作会影响该实例当前所在房间。

## 同步配置

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `context_sync_enabled` | `false` | 人格与双向记忆总开关 |
| `context_persona_id` | 空 | 旧唯一绑定的默认人格；独立来源规则不使用此覆盖 |
| `context_sources` | `{}` | 独立来源规则；人格单选、记忆多选并全部读写 |
| `context_memory_provider` | `auto` | 自动、只同步人格、Memory Companion 或 LivingMemory |
| `context_platform_id` | 空 | 单个 aiocqhttp 实例自动确定；多个时指定 |
| `context_identity_links` | `{}` | Oopz UID 到 QQ 号的显式关联 |

`group_map` 推荐使用完整 UMO 作为键，值保留 `area`／`areas`、`channel`、`label`，并支持 `allow_control`；旧数字键与扩展字段保留。`context_sources.rules` 保存范围、`persona_umo`、`persona_id`、`memory_umos` 和私聊确认 `allow_private`，推荐通过页面维护。

## 排查问题

- **无法连接 Ooptra**：核对服务地址、控制台密码和防火墙；先运行 `/语音自检`。
- **同步未接管**：核对开关、实际房间绑定与 QQ 平台实例，保存后刷新语音上下文。
- **多个记忆插件**：手选一个主插件，避免同一轮重复写入不同记忆库。
- **没有找到记忆**：检查群作用域、QQ 群人格、白名单和采集设置；空检索结果不证明没有历史记录。
- **暂时断线**：当前会话可保留已加载人格，记忆查询会明确失败；语音采集进入 Ooptra 本地待写队列，重连后重试。
- **普通聊天未立即变成长期记忆**：先区分“对话已采集”与“长期记忆已生成”；后者由记忆插件的总结策略决定。

开发、协议和验证边界见 [同步开发说明](docs/context-sync.md)，版本变化见 [CHANGELOG](CHANGELOG.md)。[GitHub Actions CI](https://github.com/Eason4869/astrbot_plugin_ooptra/actions/workflows/ci.yml) 在 `main`、`beta`、`dev` 推送及 Pull Request 时运行全部 Python 单元测试（Ubuntu Python 3.10／3.13、Windows Python 3.13）、Node 22 控制台适配器测试和前端脚本语法检查。自动化验证使用模拟运行时，不等于真实 QQ 群和 Oopz 语音房验收。
